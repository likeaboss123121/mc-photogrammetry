## API and domain

The new module is `src/mc_photogrammetry/reconstruction/evaluation_remap_support_v2.py`. Its immutable records are:

- `KernelIdentity`: exact source/build/artifact pins; only `REFERENCE_KERNEL` field values are recognized. The installed wheel identity is refused.
- `BufferView(data, shape, row_stride, address, kind)`: immutable detached bytes for the exact native row span, including inter-row padding. Source kind is `u8`; planar map kind is `f32le`. Pixel strides are fixed at one/four bytes; row strides may be padded. Address metadata refers to the original native buffer, not the detached Python snapshot.
- `OutputLayout(shape, row_stride, address)`: declared destination layout only; there are no output pixels and no sampling.
- `SupportRequest(kernel, source, map_x, map_y, destination, ...)`: explicitly requires known `fp_policy`, `active_dispatch` and resolved accurate hint. Their defaults are `None` and refuse, rather than supplying runtime certainty. Mat, accurate INTER_LINEAR, absolute distinct planar maps and BORDER_CONSTANT only. Raw border values are int32 integers, saturated to uint8; fractional/nonfinite/ambiguous borders refuse.
- `build_symbolic_support(request, max_extra_bytes=256 MiB)` returns a frozen `SymbolicSupport(payload: bytes, request_sha256, planned_extra_bytes, seal_sha256)` or typed `SupportRefusal`. The payload is schema3 packed CSR; the prior tuple/object representation is superseded without changing its admitted numerical row semantics.
- `verify_symbolic_support(request, witness, max_extra_bytes=...)` bounds/validates the packed header first, checks its seal, then recomputes one row at a time and compares bases, fraction bits, both CSR pointers and every exact term. It never invokes the builder or materializes unpacked arrays. Rehashing changed bytes does not make their semantics valid.

Supported dispatcher labels are BASELINE, SSE4_1 and AVX2. The only FP-policy label is `binary32-rne; reject-subnormal-coordinates-and-fractions`. This binds a precisely declared coordinate-arithmetic model; it is not a native FP/dispatch attestation. Trusted, separately sealed native ingress and eventual runtime validation must establish that these declarations match reality. The builder cannot verify live pointers, allocations, MXCSR, loaded binaries or hardware, and never attempts to do so.

Native-buffer ranges must be disjoint, including padding, source/destination and both maps. Identical planar starts and partial overlap refuse. Shapes must satisfy OpenCV's positive SHRT_MAX bound; source/map/destination spans, alignment, little-endian float32 representation, row strides, pointer extent and signed32 source-stride/coordinate products and sums are checked. Metadata is never inferred from snapshot content. Nonfinite maps, subnormal coordinates/fractions, unknown FP policy, relative maps, DEFAULT/APPROX unresolved hints, unsupported layout/dtype and unsafe arithmetic refuse. A native `(-1,-1)` map is processed by its coordinates; it is not a separate sentinel rule.

## Numerical and sealing contract

The implementation uses standard-library integers, `Fraction`, and byte unpacking only. It models IEEE binary32 round-to-nearest/ties-to-even in software, including native int-to-float conversion and rounded subtraction after floor. Signed-zero fraction bits are preserved. For example x=-2^-26 gives base=-1 and native rounded alpha=1; it does not use the exact-real fraction 1-2^-26.

For native fraction values a,b, the logical corner order is `(dy,dx)=(0,0),(0,1),(1,0),(1,1)`. Coefficients are exact dyadics `(1-a)(1-b), a(1-b), (1-a)b, ab`, represented as reduced numerator / 2**shift. No floating product, epsilon, 1/32 table, coefficient rounding or source-pixel-value test controls membership. Smallest-normal a=b=2^-126 retains the nonzero diagonal weight2^-252 although an ordinary binary32 product would round to zero. This is symbolic support, not a claim that changing that source pixel must change uint8 bytes.

CSR rows follow destination raster order. In-image nonzero corners become logical source indices y*width+x, ordered by corner, with weight and corner tag. Out-of-image nonzero corners become distinct constant-border terms; no coordinate clipping or replacement source index. Exact-zero corners are omitted. `(-1,-1)` therefore has empty image membership and one weight1 constant term. Zero-valued source pixels retain membership. Native source addresses/strides are separately bound and never confused with logical pixel indices.

A domain-separated streaming SHA-256 binds schema3, complete request/kernel/FP/layout identity, declared reservation and every packed byte. Request hashing includes complete source/map snapshot hashes and padding. The witness payload is hashed through a bounded memoryview, without serialization or concatenation. Ordinary mutation of the frozen wrapper or bytes is rejected; semantic verification also rejects independently resealed changes and foreign source/layout substitution. This protects trusted-process record semantics, not arbitrary Python introspection/global mutation.

## Packed representation and capacity

The fixed header is192 bytes (within the4096-byte allowance), little-endian `<8s9I6Q32s32s36s>`. It contains magic `OCVCPU3\0`, version3, header length, destination pixel countN, source/border term counts, source/destination shapes, six offsets/total length, request SHA-256, kernel SHA-256 and36 reserved-zero bytes. Unknown version/magic, shape/count drift, offsets, reserved bytes, truncation and trailing bytes refuse. Exact section offsets are derived from trusted counts; no arbitrary displacement is followed.

Sections are: bases ix/iy signed32 plus alpha/beta rawuint32 (16N bytes); source CSR and border CSR uint32 pointers (8(N+1)); source terms followed by border terms. Each40-byte term is `<32sBBBBI>`: unsigned little-endian256-bit exact numerator; denominator shift0..252; corner0..3; kind0source/1constant; source reserved0 or saturated constant-u8; logical source index or fixedUINT32_MAX for constants. Every coefficient must be positive, reduced, <=1; all fields must equal the approved row oracle. Corner order, destination raster order, row endpoints and table counts are canonical. There are at most4N total terms. Zero pixels never erase membership and OOB terms never clip to a source pixel.

MaximumN is262144 (512x512), matching the declared evaluator patch cap, not whole-frame dimensions. Per native source/map/destination span stays16MiB. The worst payload bound is

```text
W(N) = 4096 + 184*N + 8
W(262144) = 48,238,600 bytes
I = source span + map_x span + map_y span <= 48 MiB
R = 2*I + 2*W(N) + 16 MiB
R_max = 213,917,712 bytes < 256 MiB
```

Trusted metadata/count/span/identity validation and an atomic aggregate reservation precede coordinates or payload allocation. Pass1 traverses immutable map bytes, validates every coordinate and counts source/border terms with constant-space row locals. Then one exact bytearray is allocated; pass2 repacks the same immutable inputs directly into it. There is one bytes freeze, immediately followed by dropping the mutable buffer. No full serialization, additional payload concatenation, retained per-pixel Python tuples/Fractions/Dyadics, or full decoded verification copy exists. At most one row's two small term lists (four terms total) and four exact weights are retained by the row oracle; a preceding caller row can coexist during evaluation of its successor.

The twoW allowance covers exact mutable construction and immutable freeze. The twoI allowance conservatively covers an admitted snapshot set and an ingress duplicate, even though this module never creates that duplicate. Before allocation the retained bulk buffers are input bytes only; during packing there is one exact bytearray; at freeze both bytearray+bytes coexist; afterward only packed bytes remain. Verification borrows the immutable packed bytes via memoryview and uses row locals, never a new payload or decoded table. Payload/object headers, constant-size header records, streaming hash objects, row temporaries and ledger metadata fit the separate16MiB scratch allowance.

## Aggregate ownership boundary

One coordinator-owned process-global ledger stores one immutable authoritative snapshot: permanent `(exact witness, charge)` entries plus an optional current `(token, phase, charge, exact witness)` transaction. Used bytes derive from that snapshot. Admission publishes a provisional build charge (or exclusive verification borrow/temporary charge) in one reference replacement; commit publishes the complete exact witness and committed charge together in one reference replacement. There are no caller `active`/`committed` flags whose later assignments decide accounting. A short mutex protects snapshot transitions; the current token preserves exclusive ownership through all row work, cleanup and finalization. Other nested/concurrent transactions refuse while that token owns the envelope, including while cleanup is in progress.

The precreated context token spans admission through completion. If admission throws after publishing its charge but before returning to its caller, `__enter__` clears inactive frames and cancels using authoritative ledger identity. Ordinary provisional failure clears inactive buffer-owning worker/exception frames before cancellation; a failed admission cannot cancel another owner's token. Commit is the authoritative registration point: an exception immediately after commit still preserves the registered complete witness and its permanent charge, even if the API has not returned that witness to its caller. Context finalization moves the committed exact witness into permanent entries without changing the accounted charge. This is the explicit registered-witness contract required by the latest handoff revision; it does not depend on a wrapper boolean or GC lifetime.

Successful registration is permanent; no public reset/refund/release or fallback ledger exists. A precommit refusal internally rolls back only after scratch/output cleanup. The ledger reuses a permanent reservation only for the exact authenticated object under exclusive ownership; equal bytes/hash/replacement wrapper cannot authenticate ownership. Unknown/external verification receives a separately admitted temporary charge and returns it after its worker is quiescent. Its caller-supplied input payload is outside this component's ownership contract unless separately accounted by that caller.

Cancellation is deliberately bounded: one cleanup/finalization attempt, not arbitrary immunity to repeated async interruption. If cleanup itself is interrupted before authoritative finalization, the current token and charge remain fail-closed; subsequent operations refuse `ownership_busy`. If interruption occurs after publication of finalization, the snapshot already expresses the correct permanent/rolled-back state. There is no public recovery/reset for a stranded token; such an evaluator lifetime cannot continue without separately reviewed coordination. This avoids both uncharged retained bytes and unsupported unconditional cancellation claims.

An original packed bytes reference remains under its permanent charge even after callers drop wrapper references. Additional caller-created copies are outside this component's ownership/accounting contract and must be separately reserved; the API cannot prevent arbitrary Python copies. A successfully returned worst-envelope512x512 witness fits once; a second worst-envelope request refuses, even after references are dropped. This conservative lifecycle is accepted only for the pure evaluator checkpoint. It is not multi-view capture readiness. Future capture must use separately reviewed opaque ownership/streaming or controlled worker lifetimes, and separately reserve evidence/native/decompression buffers. No lifecycle integration is implemented here.
