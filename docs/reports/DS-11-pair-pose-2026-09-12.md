`src/mc_photogrammetry/pipeline/connected_camera.py`, new `tests/test_connected_camera.py`, the
correction section appended to `docs/reports/DS-10-connected-camera-design-2026-09-12.md`, and this

working tree after DS-9/DS-10 (HEAD `c6dba2c` plus the accepted DS-3/4F/5/7/9/10 edits).

## 1. What was built

One module and one public entry point: `solve_pair(left, right, matches, *, left_id, right_id,
gates)` takes two `CameraEstimate` values and `N x 4` pixel correspondences and returns a `PairPose`
that is either **solved** (right yaw class, relative rotation `R = R_r R_l^T`, unit world baseline
`b = C_r - C_l`) or **unresolved** (typed reason, no vector). It enumerates the right view's four
yaw quadrants, solves and gates each, anchors the left view at class 0, and accepts only a winner
with a clear residual margin over the runner-up. It consumes DS-9's per-view estimates; it does not
calibrate, match features, build components, recover scale, or read a manifest, lattice, or asserted
metadata. Diagnostics for every quadrant travel in `PairPose.classes` (`YawClassScore`).

## 2. Pose and sign, in this repository's convention

`camera.camera_rotation_matrix` returns the world-to-camera matrix `R` with rows (right, up,
forward), so `x = R (X - C)` and the pixel ray is `u = normalize(((px - cx)/fx, -(py - cy)/fy, 1))`
in the image-up frame of `camera.py:255-298`. Substituting the right camera into the left camera's
coordinates gives exactly `P_l = [I | 0]`, `P_r = [R | t]` with

    R = R_r R_l^T,      t = R_r (C_l - C_r) = -R_r (C_r - C_l).

`t` is the baseline in the **right** frame, pointing from the right eye to the left eye - this is the
DS-10 correction C1, replacing DS-10's left-camera `R_i (C_j - C_i)`. The frame-independent world
direction from left to right is `b = C_r - C_l = -R_r^T t`, and that is what the result reports.

For rays `u` (left) and `u'` (right), `x' = R x + t` and coplanarity give `u'^T [t]_x R u = 0`, i.e.

    a^T t = 0,      a = (R u) x u'.

`t` is the unit right-singular vector of the stacked `A`, fixed up to sign by cheirality: with
`C_l = 0`, `C_r = b` (unit baseline) the left depth is `lambda_l` in `lambda_l d_l = b + lambda_r
d_r`, solved per correspondence by the normal equations. The wrong sign flips both depths, so the
solver keeps the sign with the larger positive-depth fraction.

## 3. Yaw quadrants are a right multiplication

Calibration reports yaw modulo 90 degrees. Here `R(yaw) = Rz(roll) D Rx(-pitch) Ry(yaw)` with
`D = diag(-1, 1, 1)`, so

    R(yaw + 90 k) = R(yaw) Ry(90 k),      k in {0, 1, 2, 3},

verified numerically against `camera_rotation_matrix` by the test
`test_yaw_quadrant_copy_is_a_right_multiplication`. DS-10's `Ry(90k) R` would be `R(yaw - 90k)` and
is a different candidate set (correction C2). Because `R = R_r R_l^T` depends on the chosen class,
the class cannot be scored against a fixed derived rotation: each candidate is solved and gated
jointly, and the left anchor stays a gauge. Shifting the left estimate by `+90` degrees keeps the
relative rotation and rotates the baseline by `Ry(-90)`, which the gauge control asserts.

## 4. Estimator, residuals and gates

For each class the constraint rows are solved by deterministic seeded RANSAC (default seed 0, 512
minimal samples of 5, plus the all-row SVD as a candidate) followed by an SVD refit to a fixed point.
The per-row residual is `|a^T t| / ||a||`, reported in degrees. Class comparison and the ambiguity
margin use the median over **all** informative correspondences, not the model's own inlier median:
a wrong quadrant can always shrink its median by discarding matches, which is exactly what made an
early version report false ambiguity. `PairGates` defaults: 8 correspondences, 1.0 degree inlier
band, 8 inliers, 0.5 inlier fraction, 1.0 degree max median residual, 3.0 degrees median parallax,
0.75 cheirality fraction, `s1/s0 >= 1e-3` conditioning, 0.25 degree margin over the runner-up.

Refusals, in gate order: zero-length constraint rows (a rotation that maps every left ray exactly
onto its right ray) are `pure_rotation`; rank/conditioning failure is `rank_deficient`; then
parallax, support, fraction, residual and cheirality. Input faults return `missing_pose`,
`missing_intrinsics`, `invalid_intrinsics`, `invalid_pose`, `invalid_matches`, `non_finite_input` or
`insufficient_correspondences`. A near-tie between quadrants returns `ambiguous_yaw_class`. Every
reason is listed in `REFUSAL_REASONS`, and unresolved results carry `None` for every vector.

## 6. Corrections applied to DS-10

The appended DS-10 Section 7 states C1 (right-frame baseline `t = R_r(C_l - C_r)`, world `b = -R_r^T
t`), C2 (candidate-dependent `R`; quadrant copies are right multiplications), C3 (rounded block IDs
cannot gate repetition before scale/frame recovery, so this solver uses no lattice evidence) and C4
(single-plane structure is degenerate only when the plane contains the baseline; use conditioning
and parallax). The module and tests implement exactly these; the DS-10 Section 5 package (graph,
components, quadrant scoring over a fixed rotation, repetition audit, scale) is not implemented.

## 7. Non-claims and next step

This is a pair solver only. It establishes no component positions, no per-component scale, no
`scale_known`, and no production accuracy: the M3 gate and real-fixture behaviour are unmeasured.
Feature matching, lattice-constrained correspondences, multi-view position/scale resolution, schema,
CLI/desktop, and any `sfm`/`raycast`/`calibration` edit remain out of scope and untouched. The next
bounded package would be the component layer over these verified edges, with its own controls.
